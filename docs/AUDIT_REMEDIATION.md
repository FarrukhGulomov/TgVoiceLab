## Behaviour changes you may notice

- `POST /v1/operations/kill-switch` returns `{on, cancelledRequests, liveStopRequested}` (the `terminated`/`elapsedMs` fields moved to the in-process service only: the provider hangup now runs after commit).
- Revoking permissions returns `{version, cancelledRequests}`.
- A dial attempt before approval no longer kills the request; it stays pending.
- Kill switch / revoke / opt-out now revoke the authorization of cancelled requests: a cancelled request needs a new request and approval.
- Production now refuses to start with an owner mismatch or a privileged database login.

## Validation actually run

`pnpm lint`, `pnpm format`, `pnpm typecheck`, `pnpm build`, **411 tests** (unit, contract, integration, e2e) on Node 22 against PostgreSQL 16, `pnpm audit --prod --audit-level high` (no known vulnerabilities), the secret scan, and `deploy/smoke.sh` on real containers (13 checks). Not run: a real Telegram canary, any real call, a production host.

Production call adapter, audio bridge, Realtime, consent recognizer and the live gates G0-B…G0-F are still open (`docs/research/telegram-private-calls.md` §9a). Calling stays disabled.
